# 教学设计（给 Agent 判断，不向用户讲行话）

> Step 2 读「叙事结构」。某一段不知道怎么写时再读「知识类型」和「解释方式」。

一段只推进一个想法。想法用下一句接上，不要为此新开一节。讲稿原文进 notes，不上屏。

---

## 叙事结构（Step 2）

| 结构 | 最适合 | 核心逻辑 | 钩子 |
|---|---|---|---|
| 反差型 | 纠正误解 | 你以为→其实 | 「你以为 X，其实 Y」 |
| 问题-解答型 | 教一个概念/方法 | 为什么→因为→所以 | 「为什么 X？答案不在表面上」 |
| 递进/解包型 | 复杂概念 | 表面→本质→延伸 | 「X 背后还有一件更重要的事」 |
| 身份认同型 | 赋能 | 你也有这个→这是优势 | 「你比你以为的更适合做 X」 |
| 故事型 | 经历、案例 | 情境→冲突→转折→启示 | 「那天发生了一件奇怪的事」 |
| 框架型 | 方法论 | N 个要素→每个→怎么用 | 「把 X 拆开，只有 N 件事」 |
| 对比型 | 两个选项 | A vs B | 「A 和 B，你可能选错了」 |
| 时间线型 | 演化 | 过去→现在→未来 | 「X 年前没人想到 Y」 |

学习路径优先选能「带着走」的：问题-解答、递进、框架、故事。纯讲座式的「封面-议程-致谢」不要用。

---

## 知识类型 → 这一段怎么写

### 概念（X 是什么）
人能用自己的话解释，能辨对错例子。
优先：类比、正反例、边界案例。不要贴定义。

### 程序（怎么做 X）
人能不看提示做一遍。
优先：同一步骤写在同一章里，先错后对，中间设一个判断。不要一步新开一节。

### 叙事（故事、案例）
人能回忆情节并抽出教训。
优先：把人放进情境，转折写成单独的一段。不要压成三条要点，也不要为此新开一章。

### 关系（X 和 Y）
人能说出方向、强度、条件。
优先：先出现节点，再长出连线；或 2×2 一格一格亮。不要一张静态箭头图。

### 元认知（为什么要这样想）
人能察觉并调整自己的想法。
优先：旧想法 / 新想法并置，让人先猜再揭。不要说教。

### 数据（数字、规模）
人能感到大小和变化。
优先：用面积、计数、日常参照物。不要贴表。

## 解释方式（这一段要完成的事）

| 这一段要完成 | 怎么做 |
|---|---|
| 建立类比 | 已知在左，新概念在右，再画出对应 |
| 展示过程 | 起点 → 触发 → 中间变化 → 结果，可重播 |
| 对比差异 | 先同时出现，再高亮真正不同的那一点 |
| 建立框架 | 先乱，再归位，再给每格一个例子 |
| 讲演化 | 时间轴向右长，节点停顿并说「为什么在这里变」 |
| 让人动手 | 这一段里要有一个能完成的小动作（选、填、点开、对照） |

## 判断时用的原则（不对用户说这些词）

| 原则 | 在路径里怎么做 |
|---|---|
| 工作记忆有限 | 一段只推进一个想法。想法靠下一句接上，不靠新开一页 |
| 视觉和语言是两条通道 | 图/动画说一件事，口播或 notes 说另一件，不重复 |
| 新知识要挂在旧知识上 | 每个新概念找一个日常类比 |
| 先定终点 | 先问「读完要能做什么」，再决定有哪几章 |
| 好奇缺口 | 钩子制造问题，不立刻给答案 |
| 让人先猜 | 揭示之前留一拍 |

## 和幻灯片提纲的差别

幻灯片提纲的一行，是一张要单独成立的页。这里的一行，是下一句要接上的话。

- 章按「读完要能做什么」来分，不按讲稿的自然段来分
- 段与段靠意思接上。页面上不出现「下一页」「下一步」
- 中途要有出口：链接、任务、工具，让人离开页面也能继续做
- 自己看时整篇往下读。被人带着走时，先把这一段里还没说的揭开，揭完再滑到下一段。滑过去不是因为「到点了」，是因为这一段的意思已经齐了
